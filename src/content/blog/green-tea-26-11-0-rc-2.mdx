RC.1 froze green-tea's API. The next thing I did was the thing I should do before any release
called *stable*: sit down and try to break it, from every side I could think of. Security,
stability under load, release engineering, the mesh.

It broke in nine places. `26.11.0-rc.2` fixes all of them, and this post is the list.

## Who should upgrade

Everyone on `26.11.0-rc.1` or any `26.x` beta. There is no patched beta: the fixes ship only in
`26.11.0-rc.2`, so a beta user also crosses RC.1's breaking changes. The
[What's new](/docs/whats-new/) page and the CHANGELOG list them.

```bash
npm install @green-tea/core@rc
```

On Deno, `jsr:@green-tea/core@26.11.0-rc.2`. The official plugins moved with it: `@green-tea/jwt`,
`metrics` and `rate-limit` are 26.11.0-rc.2 on JSR and accept any core from `^26.11.0-rc.2`.

## What behaves differently

Most of the security fixes change nothing you would notice. Five do, and they are in the
[CHANGELOG](https://github.com/Expressive-Tea/green-tea/blob/main/CHANGELOG.md) along with two smaller
changes: `channel()` now buffers 1024 values per subscriber by default, and `/__ready__` no longer
lists degraded provider names. [What's new](/docs/whats-new/) has a table of who each change
affects and what to do.

- **A cross-site WebSocket upgrade gets `403`.** An upgrade with an `Origin` must come from the same
  host or from an origin in `cors.origins`. Clients that send no `Origin`, such as servers and CLIs,
  are unaffected. Behind a proxy that rewrites `Host`, add your public origin to `cors.origins`.
- **`ctx.ip` is the right-most `X-Forwarded-For` entry**, the one your proxy appended. Behind a chain
  of proxies it is now the address the last one saw.
- **`origins: '*'` with `credentials: true` fails `createApp`.** If you really mean every site, say it
  as a predicate: `origins: () => true`. This one is breaking, on purpose.
- **A failed stream ends with `Internal Server Error`** unless you threw an `HttpError`, the same as a
  buffered route.
- **`static` answers `404` for dotfiles**, except under `/.well-known/`.

## Why now, and not after stable

Because finding these is what the RC is for. The API freeze promised that nothing would move between
RC.1 and stable except fixes, and every one of these is a fix: none adds, removes or renames an API.
The one that refuses a configuration at boot is called out as breaking, and I would rather break a
config that hands your users' cookies to every site than keep it working.

The same audit found the other half of what "stable" means: a release that could not be staged, a
support policy that did not exist, a version scheme that let `npm install` pull in a breaking change.
Those are fixed too. After stable, **only the first release of a year can break**, so the `^` range
npm writes for you is safe within a year, and the
[support table](https://github.com/Expressive-Tea/green-tea/blob/main/SECURITY.md#supported-versions)
says which releases get fixes, and for how long.

## The mesh, on the way to beta

The mesh stays experimental, but `26.11.0-rc.2` takes it most of the way to a beta: a teapot reached over
`ws://` from another machine is refused unless you opt in, mesh on the edge fails with an error that
says so, a remote step runs only what it needs, and there is a [runnable demo](/docs/guides/mesh/)
of one REST API split across two processes, with the teapot killed and brought back.

If you find something I missed, [SECURITY.md](https://github.com/Expressive-Tea/green-tea/blob/main/SECURITY.md)
says how to tell me privately.
